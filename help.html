SideKick_GC — User Manual

A desktop application for managing GoCardless Direct Debit mandates, payment plans, and customer notifications.

Last updated: 2026-09-29

Getting Started

First Launch

  1. Double-click the desktop shortcut or run python -m sidekick_gc
  2. Go to the Settings tab
  3. Paste your GoCardless API token — it saves automatically
  4. Click Test Connection to verify
  5. If using GHL integration, enter your API Key and Location ID, then click Test Connection

The status bar at the bottom shows LIVE (green) or SANDBOX (orange) to indicate which environment you're connected to.

System Tray

When you close the window, the app minimizes to the system tray (bottom-right of taskbar). The tray icon menu provides:

  • Show Window — restore the app
  • Notifications: On/Off — current polling status
  • Settings — jump to Settings tab
  • Restart — restart the application
  • Exit — fully close the app

Double-click the tray icon to show the window.

Client Tab

Search for customers and manage their mandate status.

Searching for a Client

Option 1: Manual entry

  • Type the client's email address in the Email field
  • Click Check Mandate

Option 2: GHL search

  • Type a name or email in the search box
  • Click Search GHL — a dialog shows matching contacts
  • Select a contact to populate their details

Mandate Status

After checking, the status panel shows:

  • Mandate Found — customer has an active Direct Debit mandate, with bank name and any active plans listed
  • No Mandate — customer exists but has no active mandate
  • No Customer — email not found in GoCardless

Note: When used via the SideKick PS toolbar, a "No Customer" result automatically triggers a name-based search. If a match is found under a different email, a confirmation dialog is shown before proceeding.

Creating a Billing Request

If the customer has no mandate:

  1. Fill in First Name, Last Name, and Email
  2. Click Create Billing Request
  3. A mandate setup link is generated
  4. Use Copy Link, QR Code, or Send via GHL (email/SMS) to share it with the customer

Sending Notifications

If GHL templates are configured in Settings:

  • Send Email — sends the configured email template via GHL
  • Send SMS — sends the configured SMS template via GHL

Payment Plans Tab

Create instalment schedules against a customer's active mandate.

Creating a Plan

  1. Plan Name (top-right) — enter a reference (e.g., P26001-Smith). Only bank-statement-safe characters allowed: A-Z 0-9 - . & /. The statement preview shows what appears on the customer's bank statement (Statement Label prefix + plan name).

  2. Plan Details (left column):

  3. Total Amount — the full balance in pounds (e.g., 500.00)
  4. Number of Payments — how many instalments (1–60)
  5. Recurring — Monthly, Weekly, Bi-Weekly, or 4-Weekly
  6. Day of Month — which day payments are collected (1st–28th or Last Day)

  7. Start Date — when the first instalment is collected

  8. Payment Schedule (right column) — auto-updates as you change values, showing each payment date and amount

  9. Downpayment (optional):

  10. Enter an amount to collect upfront
  11. Choose payment method (Credit Card, GoCardless DD, Bank Transfer)
  12. Set the date

  13. Rounding — when the total doesn't divide evenly, the leftover pennies go to either the Downpayment or the 1st Payment (toggle with radio buttons)

  14. Click Create Payment Plan to submit

Single payments: When there is only 1 payment, SideKick_GC creates a one-off payment via the Payments API instead of an instalment schedule.

Schedule Preview

The table shows:

  • Row number, date, and amount for each payment
  • A summary line showing total payments and the grand total

Payments Tab

Create payments against a mandate — mirrors the GoCardless dashboard's "Create payment" and "Create subscription" flows in one tab with a mode toggle.

Single Payment vs Subscription

  • Single payment — one amount on one charge date (deposits, one-off balances, or one-time collections).
  • Subscription — recurring collections. Choose an interval (Weekly / Monthly / Yearly), a day of the month (or Last Day), a start date, and the number of payments.

Enter the amount and an optional description. The tab operates on the active client's mandate, loaded from the Client tab.

Refunds Tab

Find a client, view the payments collected so far, and issue a full or partial refund — with the option to extend their payment plan afterwards.

  • Search for the client (or use the active client from the Client tab).
  • The payments table lists collected payments with amounts and dates.
  • Issue a full or partial refund against a payment.
  • Optionally extend the pay plan to reschedule the remaining balance.

Stale Mandates Tab

Find and clean up mandates that are still active but have no remaining payment plans.

Usage

  1. Click Refresh to scan all active mandates
  2. The table shows mandates where all plans have finished, including:
  3. Customer name and email
  4. Bank name
  5. Last payment date
  6. Total collected
  7. Tick the mandates you want to cancel
  8. Use Select All / Select None for bulk selection
  9. Click Cancel Selected to revoke them (this is irreversible)

A progress bar shows status during both scanning and cancellation.

Notifications Tab

Automatically detect when a customer's bank cancels their Direct Debit mandate and tag their GHL contact.

The tab scrolls when the window is too small — nothing gets cut off. The ⚙️ Polling & Sync Settings card is collapsible: click its header to hide the settings cards and give the event tables more room.

Setup

  1. Enable automatic polling — tick the checkbox
  2. GHL section:
  3. Cancel Tag — select or type the GHL tag to apply (e.g., DD Cancelled). Use the refresh button to load tags from GHL.
  4. Frequency section:
  5. Poll Every — how often to check (e.g., 24 hours)
  6. Start Time — when the first poll of the day runs (e.g., 08:00)

All settings save automatically when changed.

How It Works

  • The app polls the GoCardless Events API for mandates cancelled by the customer's bank (not cancellations you initiated)
  • For each found cancellation, it searches GHL for the customer by email
  • If found and not already tagged, it applies the configured tag
  • Results appear in the table showing: cancellation date, customer name, email, cause, mandate ID, and tagging status

Manual Poll

Click Poll Now to check immediately without waiting for the timer. The first poll looks back 30 days; subsequent polls look back 2× the polling interval.

Status Indicators

The GHL Tag column shows:

  • Tagged — tag successfully applied
  • Already tagged — contact already had the tag
  • Failed — could not apply tag (hover for details)
  • Skipping — duplicate mandate already processed this session

Bank Transfers (studio workflow)

Visible only when Xero & Bank Integration is enabled in Settings. The daily bank poll matches incoming Metro transfers to clients and classifies them:

  • Recorded in PSA — already logged; no action
  • Settlement — matches an active GoCardless plan; click Open Client to confirm via the Settle button
  • Manual payer — recorded with an updated statement (automatic only when the match is verified)
  • Part payment / Unmatched — shown for review; nothing runs unattended

Check Bank Now runs the poll immediately. Transfers that cannot be verified (e.g. an archive drive is offline) stay pending until the next poll.

Stats Tab

Monthly income statistics, charted from GoCardless payments that have been paid out.

  • Time Range — 1, 2, or 3 years.
  • FY Start — the month your financial year starts (default April, the UK tax year).
  • Compare with previous year — overlays the prior year's income for year-over-year comparison.
  • Refresh — reloads from GoCardless (results are cached for 5 minutes).

Summary cards show YTD Total, Monthly Avg, Best Month, YoY Growth, Total Debt, Bad Debt, and Schedule To. A bar chart plots monthly income, and a table breaks it down month by month.

Requires a GoCardless token (configured in Settings).

Banking Tab

A read-only browser over the local bank ledger (the SideKick_Xero SQLite database). It works like a bank-statement viewer:

  • Account dropdown, plus filters by date, type, and text.
  • Sortable columns: date, reference, money in/out, payee, type, info, value date, balance.

It only reads the local ledger — no API calls and no writes. Ingestion happens via the daily poll/settle scripts (see Bank Transfers above and the Bank Feed settings below).

Settings Tab

Settings uses a left-hand menu with five pages. Pages scroll when the window is too small — nothing gets compressed.

🔑 API

All API credentials live here:

  • GoCardless API Token — paste your token; it saves automatically when you click away. Test Connection verifies it works and GoCardless Dashboard opens the GC web portal.
  • Environment — live (real payments) or sandbox (testing only, no real money moves).
  • GoHighLevel (GHL) Integration — API Key (v2, from Settings > Business Profile > API Key) and Location ID. Test Connection verifies GHL credentials. Required for Client tab GHL search, contact notifications, and Notifications tab tagging.
  • AI / LLM API Key — key for the AI Chat feature, with a link to get a key from your provider. Test Connection verifies it.
  • Bank Feed — choose the provider for the Banking tab:
  • Nordigen (default) — the Metro bank feed for the studio. secret_id + secret_key, 🏦 Connect Bank (guided setup wizard) and Test Connection. Shows the 90-day consent-expiry date and warns when it is close to expiring. Existing credentials are pre-filled from the bank-feed files; re-run the wizard to renew consent.
  • Starling — for a Starling account without the studio ledger. Paste a personal access token and the Banking tab reads balances and transactions directly from Starling. See "Starling Bank Feed" below.

Warning: Always verify you're on the correct environment before creating payments.

⭐ Starling Bank Feed

The Banking tab can read balances and transactions straight from a Starling account — no studio ledger, no extra software. SideKick_GC needs a personal access token (a long password Starling issues for apps).

Choose Starling as the provider:

  1. Settings → 🔑 API → Bank Feed → set Provider to Starling.
  2. Click 🔗 Get PAT (opens the Starling developer site).

Create the token once (on developer.starlingbank.com):

  1. Sign in with your normal Starling login.
  2. Open the Personal Access page (developer.starlingbank.com/personal/token).
  3. Create a new token. Starling asks you to confirm by scanning a QR code with the Starling app on your phone — this links the token to your business account.
  4. Only tick the read permissions: account:read, balance:read, transaction:read. Do not tick anything that says "write" or "edit" — SideKick_GC only needs to look, never change.
  5. Copy the token and paste it into the Access Token box in SideKick_GC.
  6. Click 🔌 Test Connection — a green message means it worked.

The Banking tab then shows the account with a running balance. Transactions are cached on this computer, so the tab opens fast and updates as new transactions settle.

🧾 Billing

  • Statement Label — prefix shown on customer bank statements (e.g., Zoom-Photography-). Banks typically show 10–18 characters total.
  • Mandate Link — fixed mandate signup URL for your business.
  • Currency — default currency for payments (GBP, EUR, USD, etc.).
  • Default Payment Window — days before the next scheduled payment that the cancellation deadline falls (min 3 working days).
  • GHL Statement Tag — tag applied to the GHL contact when sending a settlement statement.

📇 GHL

  • GHL Field Mapping — choose the GHL custom fields that store GoCardless data (mandate ID, balance due, plan end date, payments progress, shoot number, extensions, failed-payment details, payer email, message). Select (refresh) to reload the field list from GHL.
  • Notification Templates — Email / SMS / Refund templates used when sending mandate setup notifications from the Client tab. Select (refresh) to load available templates from GHL.

� Set Up GHL Tags & Fields

New to SideKick_GC? This wizard does the GoHighLevel setup for you.

  1. On the 📇 GHL page, click 🪄 Set Up GHL Tags & Fields….
  2. Check — the first page tests your GHL connection and lists the permissions (scopes) the wizard needs. If anything shows red, follow the on-screen steps to add the scope in GHL (Settings → Private Integrations).
  3. Preview — SideKick_GC shows every tag, contact field and the Payment Status picklist it needs. Items that already exist are marked ✅ and left alone; only missing ones are ticked for creation. Untick anything you don't want.
  4. Create — a progress bar shows each item as it is created.
  5. Done — a summary lists what was created. Your Field Mapping dropdowns are filled in automatically and you can start using the Client tab.

Notes:

  • Re-running the wizard is safe — existing items are skipped.
  • The Payment Status field needs a pipeline. Pick yours from the dropdown; SideKick_GC remembers the choice.
  • Tags for optional features (Postcode, Light Blue) only appear when those features are switched on in Settings.
  • If creation is refused (401), open your GHL integration's Scopes and enable Tags (write) and Custom Fields (write), then re-run the wizard.

Troubleshooting

"Token loaded" but Test Connection fails

  • Verify the token hasn't expired in the GoCardless dashboard
  • Check you're on the correct environment (live vs sandbox)

GHL tags show "Forbidden resource"

  • Verify your API key has the correct permissions
  • Confirm the Location ID matches your sub-account

Restart doesn't work from tray

  • The app releases the singleton lock before restarting. If it still fails, close fully via Exit and relaunch manually.

Notifications not polling

  • Ensure "Enable automatic polling" is ticked
  • Check that a Cancel Tag is set
  • The timer starts at the configured Start Time — if the current time has passed it, polling begins on the next interval

Payments fail with "mandate not active"

  • The customer's mandate may have been cancelled or is still pending
  • Check the mandate status on the Client tab first
