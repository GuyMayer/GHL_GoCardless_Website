SideKick_GC Changelog

Unreleased (2026-11-05)

  • New: 2-minute boot delay. After a reboot SideKick_GC waits two minutes before launching the GUI so it does not spike the CPU alongside every other startup app. CLI commands are unaffected.

1.13.0 (2026-11-04)

  • Fix: settings silently lost on customer machines. Every settings save handler swallowed write errors, and compiled builds searched the exe folder for SideKick_GC.ini before %APPDATA% — so a customer's edit could be written to a file that was never re-read, or fail on a read-only install folder, with no error shown. Compiled builds now read and write %APPDATA%\SideKick_GC\SideKick_GC.ini only; an INI found next to the exe is imported once, then archived as .stale-<timestamp>. Every save failure now logs and shows a one-shot warning.
  • About → Diagnostics card. New controls on the About tab: Save Diagnostic Report (sanitised report to the Desktop and log folder), Send Logs (uploads report and recent error logs to a private Gist for support), Open Log Folder, and Email Guy. The Automatically send error reports checkbox (off by default) makes future failures report themselves — no manual steps needed. Reports never contain credentials, tokens, or client data.
  • Show Changelog button. Settings → Application now has a Show Changelog button under Open Manual, opening the release notes in the browser (hosted alongside the manual).
  • Lead Flow bridge — live-API fixes (2026-11-04). Verified against the first real Lead Flow booking: the poller's opportunity query now sends pipeline_stage_id (the API rejects stage_id), Session Type resolves its picklist from picklistOptions, missing LF- stamp fields are reported per booking instead of silently skipped, and DEST appointments keep the source's real end time. Tests in tests/test_leadflow_bridge.py.
  • Lead Flow bridge — first live transfer (2026-11-04). Fixed the three blockers the real booking exposed: naive startTime values (2027-01-27 10:00:00) are treated as UTC instead of crashing the future-appointment filter; calendar creation now uses the v3 route POST /calendars/events/appointments (the legacy route 404s and the old route rejects V3 calendars); and team calendars get an assignedUserId resolved by matching the source staff name against DEST users.
  • Lead Flow settings page — manual poll + recent clients + master prompt (2026-11-04). A ▶ Poll now button runs the poll immediately (no timer wait) and a 🕘 Recent clients pop-up shows the last five polled clients with their transfer status (ledger recent log). The enable checkbox stays clickable when the Application master switch is off and offers to turn the master on for you instead of silently locking the page.

1.12.0 (2026-11-03)

  • Plan-correction warning SMS. Every payment-plan correction (hold, failed-payment extend, pay-down, DD-to-bank conversion, refund-driven replacement, and the CLI mutation verbs) now sends the client a short apology SMS and applies the gc-plan-correction GHL tag first — so the GoCardless emails that follow a correction never come as a surprise. Configured via Settings → Notifications (new Plan Correction SMS and Plan Correction Tag rows); wording draft and one-time GHL template setup steps in the README.
  • Once-per-client-per-day ledger. A ledger at %APPDATA%\SideKick_GC\correction_warning_state.json dedupes warnings by contact_id|date, so cancel+recreate, batch auto-extends, or repeat corrections on the same day produce exactly one text. Concurrency-safe (reserve-before-send, atomic saves).
  • Manual replacements ask first. The Payment Plans / Payments tabs add a default-off "Send correction warning SMS first" checkbox; CLI mutations warn by default and accept --no-correction-warning to skip. Warnings are best-effort — a GHL failure never blocks the correction and nothing is written to stdout.
  • Fix: GHL API key / Location ID wiped. The bulk Settings save (tab change and exit) wrote the GHL credentials from the fields even when they were empty, blanking the stored key and location. It now only saves when both are filled; clearing a field by hand still works.
  • Fix: Settings lost on restart. Opening Settings fired the instant-save handlers mid-load, which wrote still-empty tag combos back to the INI (Chase 31-60 / 61-90 / Bad Debt tags were blanked every launch). The Overdue Days and Debt Bucket field mappings were also never loaded into their dropdowns, so any later save wrote them blank. All instant-save combos are now signal-blocked during load and the two missing mappings are loaded.
  • Lead Flow moved into Settings. The top-level "Lead Flow" tab is gone; Lead Flow now lives only under Settings, in the side menu directly below GHL, using the GHL page's group-box layout.
  • Lead Flow dropdowns. SOURCE pipeline and stage, DEST pipeline, stage, calendar and the guard tag are now the usual search / (refresh) / select dropdowns instead of free-text boxes. (refresh) reloads the live pipelines, calendars and primary-account tags from GHL; picking a new pipeline reloads its stages. The guard tag stays editable so a tag not yet in GHL can be typed.
  • Lead Flow master switch. A new "Sync Lead Flow" checkbox on Settings → Application is the single master switch for the Lead Flow bridge, bound to the same leadflow_enabled config field as the Lead Flow page's own enable checkbox (changing either updates the other). When off, the poller stays stopped and the Settings → Lead Flow page is deactivated with a "Sync Lead Flow is off in Settings → Application" hint.
  • Lead Flow → primary GHL bridge (2026-11-02). SideKick_GC can now poll the Lead Flow GHL account every 15 minutes for "Shoot Booked" opportunities and copy each booking into your primary GHL account: contact upsert with LF- Source Contact ID + LF- Staff, a LF- Lead Flow Client guard tag applied before the calendar entry, an AI-written Session Story, a Studio Boudoir appointment, and a #16: BOOKED! opportunity. New Settings → Lead Flow tab (enable, source pipeline/stage, calendar, guard tag, token test). Call-recording capture into toypi's calls.db is stubbed and lands as a separate piece before go-live.
  • AI Chat settings — bigger, centred, smarter (2026-11-02). The Settings → AI Chat card is capped at 1080px and centred; the System Prompt preloads and grows to fit (no scrolling); a new Story Writer Prompt holds the client-story wording rule; the AI Chat tab hides when no API key is set; and the provider choice now persists correctly (unknown providers were silently dropped on load).
  • Weekend-aware charge dates. _safe_charge_date and the silent plan builder now roll weekend payline dates forward to the next working day, so the schedule GoCardless returns matches the dates SideKick holds in the .psa. Previously GoCardless silently shifted a Sunday first date to Monday at the API boundary and SideKick appended a duplicate first payment (Papworth P26093P, Sunday 15/11 → Monday 16/11, 2026-11-02).
  • Duplicate GoCardless customer detection (2026-11-02). api._find_customer_by_email is now _find_all_customers_by_email and returns every customer matching the email instead of stopping at the first. check_customer_mandate reports the count on MandateCheckResult.duplicate_customer_count, and the CLI (--check-mandate, --check-mandate-by-name) appends a |n field when the email has more than one customer. The ProSelect button warns when it finds duplicates, so an empty extra mandate gets cancelled instead of silently checking the wrong customer record.

v1.11.0 — Mandates tab rework, GHL wizard fix, faster launch (2026-10-28)

  • Shoot number can live on the GoCardless mandate (2026-11-02). A mandate's shoot_ref metadata is now read first when SideKick looks up a client's shoot (Mandates, Notifications, balances). This covers clients whose GoCardless name and email differ from the studio's, with no plan to carry the reference. api.set_mandate_shoot_ref() writes it; Sally Shepherd's mandate was linked to P26093P (booked as Papworth — same address in the ProSelect album).
  • Confirm-the-shoot list and GHL link for mismatched clients (2026-11-02). When a mandate's shoot can't be found automatically (a partner paying, a maiden name, a different email), the ProSelect button now lists the shoots held on the day the mandate was created (or the day before) — matched by date only, with a same first name flagged — and you pick the right one, or enter it manually. The confirmed link is saved on this PC, on the GoCardless mandate, and on the GHL contact (GC Mandate ID and Shoot Number fields, plus the GoCardless email as an additional email — the same fields used when someone else pays). GHL values that already differ are never overwritten, and no GHL contact is ever created. New match_bank_transfers.py --on-date.
  • Mandates "No plans ever": Shoot column and manual shoot number (2026-11-02). A new Shoot column (the P number) sits next to Customer. When the ProSelect button can't find a client's album automatically — the name or email changed since the shoot, for example a married name — it now asks for the shoot number once, remembers it (%APPDATA%\SideKick_GC\shoot_overrides.json), also stores it on the GoCardless mandate so every PC resolves the client, and opens the album; the Balance then uses that shoot too.
  • Mandates "No plans ever": ProSelect button and real Balance (2026-11-02). The ProSelect icon on mandate rows was permanently greyed out. It now finds the client's shoot (GHL Shoot Number field, then GoCardless, then the PSA archive by surname or email), locates the .psa and opens it; failures show in the status line under Refresh. The Balance column was showing £0.00 for clients who owe money, because PSA GoCardless DD lines were counted as paid even though no GC plan exists. Balance is now order total minus real (non-GoCardless) payments dated today or earlier, the same rule as end-of-plan statements; the Xero-history fallback follows the same rule.
  • GHL Setup Wizard now keeps and links field mappings (2026-10-28). A beta tester found every mapping showed (None) after running the wizard. The Payment Status opportunity picklist now sends options as plain strings — GHL rejected the old textBoxListOptions payload with "options must contain at least 1 elements" (verified live 2026-10-28). GHL fields and tags that already exist are now linked into empty settings slots only; existing user mappings are never overwritten. Overdue Days and Debt Bucket mappings are now saved. A tag configured for several slots maps to all of them and is created once. The result page reports how many existing fields and tags were linked.
  • Faster launch — fewer reads on start-up (2026-10-27). The Notifications tab skips its automatic poll if it was polled within the last hour (the timestamp persists across restarts), and the refresh no longer blocks the window. The Mandates tab renders from cache on first show and displays a Loading indicator while a background sync runs.
  • Mandates Balance column and date format (2026-10-27). The Balance column shows order value minus deposit (live PSA, falling back to Xero history; a dash when there is no data). Column order is aligned across the sub-tabs, and customer resolution now uses linked.customers. Date fields show as YYYY-MM-DD across all tabs.
  • --next-charge-date CLI verb (2026-10-27). --next-charge-date <email> prints NEXT_CHARGE_DATE|YYYY-MM-DD. Charge-date checks now use a 4-working-day BACS lead (weekends skipped); bank holidays are left to GoCardless.
  • Mandate history cache (2026-10-27). Historical mandate records are cached locally, and the Client tab surfaces balances still owed on inactive mandates.
  • Mandates tab — two views, one scan (2026-10-27). The Stale Mandates tab is now a single-refresh, two-view Mandates tab: Finished plans (the previous stale list — all plans finished, Direct Debit still active) and No plans ever (active mandates that never had a payment plan). One refresh runs a single sweep over every active mandate and buckets it into the two lists, so the mandate list and each mandate's plans are fetched once, not twice. The "No plans ever" view has a created-date filter (Last 6 months / All time / Custom) and per-row action buttons (ProSelect / GoCardless / GHL / Open Client / Send Statement) shared with the Notifications tab.

v1.10.0 — Shoot-reference mandate lookup, end-of-plan statements (2026-10-26)

> Also rolls up everything since v1.8.0: the code was already stamped 1.9.0

> but that version never got its own changelog entry.

  • Shoot-reference mandate fallback (Client tab, 2026-10-26). When an email/name lookup finds no GoCardless customer, the Client tab now resolves the client's shoot number (from GHL by contact id, email, or first/last name) and scans GoCardless subscription/instalment-schedule names for that reference. This loads the paying partner's mandate when the bill sits under someone else's name keyed by shoot number (e.g. Zoom-Photography-P26082P_…), so a statement can still be sent. The scan shows an indeterminate progress bar with status messages and is scoped to the last 3 years via created_at[gte] — GoCardless list endpoints reject a bare date, so the filter uses RFC 3339 (T00:00:00Z). Also stops the "paid in full" preview from rendering on a client with no mandate at all. Shoot-ref extraction moved to shoot_ref.py (shared by api.py and gui/workers.py). Tests aligned: test_clear_chase_tags (GC-Extension is now a never-stripped marker), test_payment_charge (name lookup no longer fetches payment history), and test_startup_integrity (13-field GHL registry).
  • Mandate invite now passes currency and scheme to GoCardless (2026-10-26). Sending a client invite ("New Mandate Request", or the SideKick_PS GoCardless toolbar → Send Request) failed with 422 This functionality is not supported for the given currency because create_billing_request_flow posted an empty mandate_request. This account is multi-currency, so GoCardless cannot resolve a currency at creation time. The request now carries the configured currency (default GBP) and scheme (bacs for GBP, sepa_core otherwise).
  • End-of-plan statements — detection, reconciliation and manual send (SLICE 1, 2026-10-25). New read-only end-of-plan sweep reconciles completed payment plans against the PSA archive and GoCardless, lists what (if anything) is still owed, and shows the evidence behind each figure. PSA paylines are classified by method NAME first — the real export writes GoCardless DD lines carrying methodID 13, so ID-first precedence misread every live schedule as an Account Correction. BACS counts as money received (it is a bank transfer); proposed GoCardless lines and Account Corrections do not. Balances compare to a £1.00 tolerance, because the first instalment of a GoCardless plan is rounded against an exact PSA figure and sub-pound drift is expected. A failed PSA lookup bands as unresolved and is never treated as money owed or owed back. Plans resolve to a PSA shoot by the reference embedded in the GoCardless plan name, then email, then unique surname; when those disagree the row is refused for a human decision rather than guessed. Manual statement send is limited to the Complete band (email only, no cancellation, no money movement) and uses a data-driven renderer with complete / refund-due / balance-settled blocks. A preview mode (--preview, --preview-csv) lists every candidate with zero side effects, so the feature can be reviewed before it is ever enabled. Gated by a cut-over stamp — blank means OFF. The --check-plan-completions CLI verb exposes the same sweep headlessly.
  • Charge-date failure carries a NEXT_CHARGE_DATE hint (2026-10-23). When silent plan creation fails because a payment date is before the mandate's next_possible_charge_date, the error output now includes a NEXT_CHARGE_DATE|<YYYY-MM-DD> line (the ERROR line text is unchanged). SideKick_PS reads this hint to offer a one-click fix that moves the first payment to the earliest valid date.
  • Client-tab "Put on Hold" (2026-10-23). The Client tab now lets you pause a single plan directly from the GUI. Click ⏸ Put on Hold on a selected plan to cancel that plan only (the mandate stays active), apply the GHL gc-on-hold tag, and write the Payment Status. A ▶ Restart Plan button then navigates to the Payment Plans tab pre-filled for the client. Creating any new plan — via the GUI or the --silent CLI path — clears the hold tag automatically.
  • Credentials and INI writes are now atomic with self-heal (2026-10-21). credentials.json and the INI were written non-atomically with no backup, so a truncated write could silently empty them — wiping the GHL key, GoCardless token, Nordigen secrets and the bank-feed provider selection. config.py now routes every write through _atomic_write_text (temp file + os.replace, with a .lastgood backup) and restores a truncated file from .lastgood on load.
  • Three-year sync cut-off (2026-10-17). The daily GHL sync now fetches mandates only from a cut-off date forward — nothing older is synced, updated, or escalated. Defaults to three years back; a "Look back from" date field on the Notifications tab (GHL Daily Sync panel) changes it and persists as SyncCutoffDate.
  • Escalation respects the settings toggle (2026-10-17). While escalation is disarmed the daily sync no longer pops the approval preview — candidates are cached and skipped with a status note. A manual "Show overdue candidates" button reviews the latest cached list; approving ticks the chosen rows and arms automatic escalation. The preview table matches the other tables: striped rows, selectable and copyable (Ctrl+C / right-click), auto-width columns, and a Save to CSV button.
  • Bank poll no longer buries unmatched transfers (2026-10-16). A transfer the poll couldn't match on first sighting was ledger-marked unmatched and permanently excluded from every later poll. Remittance text often arrives only after booking, so a later-matchable payment could silently miss its statement and PSA payline — one payer's six weekly bank payments went unseen for two months and her statements kept showing the stale balance. First-sighting unmatched candidates are now held for re-evaluation on the next polls; only the explicit dismiss records them. The record chain also re-reads the live PSA balance after each payline write before building the statement, so batch-recorded payments show the true running balance and GHL Balance Due ends correct, and auto-record batches now run one chain at a time so each re-read sees the previous payline already written.
  • Bank Transfers table matches the events table (2026-10-16). The transfers table now grows with its rows (the 190px clamp is gone), rows are selectable and copyable (Ctrl+C / right-click, like the other tables), and the per-row text buttons are replaced with the same flat icon set as the events table — record + statement, pay down plan, open client, dismiss — left-aligned in the cell.
  • Notifications table overhaul (2026-10-15). Bank-payer clients are hidden from the events table (email + GHL contact-id matching against bank_payers.json; the store now carries each payer's email, backfilled by one batched GHL scan per refresh). Failed-payment rows now show the client's WHOLE GoCardless history: Payments made/total, a Collected column (GC gross collected + non-GC PSA paylines — deposits/BACS/card, GC DD lines excluded) and Total = the PSA order total when known (fallback: GC plan total). Figures refresh every poll cycle. The Status column is renamed Pay Plan Status and reflects the plan's status (Cancelled/Active), plus a new Chase Progress ageing column (1-30 / 31-60 / 61-90 / 90+ bad debt). Customer names colour by payment age (yellow/orange/red; bank-payer names green/orange/red by last bank payment). New per-row GoCardless button opens the customer in manage.gocardless.com; details shorten to "Insufficient funds" / "Mandate cancelled by client" with the full sentence otherwise; rows are selectable and copyable (Ctrl+C / right-click). Weekly payers are no longer chased per failed weekly payment — failures are held (⏸ Month OK — held) while the month has had successes and are released only when a whole month fails or at the end of the term, when they are added at the end as normal makeups.
  • Shoot-number fallback chain. Missing shoot numbers now resolve via a five-leg chain: GHL search, a paginated GHL contact scan (matches any contact email including additional emails, or the GC Mandate ID custom field — the reliable join when GC is in a partner's name), GC plan name/metadata, PSA archive surname, then PSA OrderList email (catches maiden/married folder-name drift). Found refs are written back to the GHL Shoot Number field. match_bank_transfers.py gains --surname/--email lookups; the new ShootResolveWorker replaces the GHL-only worker.
  • Statement deadline roll-forward. When a payment's cancellation deadline has passed, the statement no longer reports the past date — the status line, BACS deadline row, and message footer all roll forward to the next cancellable payment (e.g. "Settle by 12 Nov (16 Nov payment)"), and the footer month follows the rolled payment. With nothing cancellable left, the deadline shows "—" and the footer drops the dated sentence.
  • Who-owes-money overhaul. New pure module collectability.py is the single source of owed/aging/escalation maths. Ended plans now report owed = plan principal − collected (with refunds subtracted; charged-back and late failures excluded by status) instead of a line-sum, so a client converted to bank payer after partial DD success shows the true remainder. Active plans keep arrears semantics (failed + in-flight makeup). New soft / hard decline split on the GoCardless failure cause — only soft causes (insufficient_funds, refer_to_payer, bank_account_transferred on an active mandate) auto-retry, and retries stop at 61 days overdue or 3 failed attempts. New A/R aging buckets (current / 1-30 / 31-60 / 61-90 / 90+) with automatic escalation tags gc-chase-1-30, gc-chase-31-60, gc-chase-61-90, gc-bad-debt (Settings-overridable) and optional new GHL contact fields Overdue Days + Debt Bucket. NotifyChaseTag becomes an umbrella "being chased: yes/no" flag kept in step with the bucket tags. Escalation starts disarmed: the first daily sync shows an approval preview in Notifications, and only approved rows are tagged. The daily sync now also pages cancelled/failed mandates and paginates payments at 500.
  • BACS pay-down (S10). A new "Pay down plan" button on bank-transfer rows for clients on an active DD plan applies the bank payment to the _tail_ of the schedule: the schedule is cancelled and recreated without the trailing instalments the payment covers, any remainder reduces the new final instalment (per-instalment amounts supported in create_instalment_schedule), and a single remaining instalment becomes a one-off. The mandate is never touched; already-submitted instalments still collect and are reported. New PayDownPlanWorker + collectability.pay_down_tail.
  • Bank Payers table fixes. Blank-shoot payers are now displayed and their shoot number resolved from the GHL contact (no more silent skip); the Date column falls back to the identified date; disabled ProSelect / Send Statement buttons explain why; conversion stores the principal−collected figure and resolves the shoot number from the GHL contact.
  • Convert DD mandate payer to bank payer. New one-click conversion, from the Notifications top-table Actions column (new bank-building icon) and from the Client tab (🏦 Convert to Bank Payer). A confirmation dialog spells out exactly what happens: cancels the active GoCardless plan(s) but keeps the mandate, stops the debt-chase email sequence, moves the client to the ad-hoc Bank Payer list, removes the chase tags (NotifyCancelTag + NotifyChaseTag) and adds the new NotifyBankPaidTag (gc-bank-paid default) in a single GHL tag write. New ConvertMandatePayerWorker + ConvertMandatePayerDialog; new Settings field "Bank Paid Tag".
  • Fixed: Client-tab statement dropped the deposit and the makeup payment. Selecting a plan filtered payments to those GoCardless links to it, but the deposit (<plan> - Deposit) and a makeup payment (Makeup payment: <date>) are created unlinked, so the statement showed fewer payments, a lower total and "PAID IN FULL / £0 remaining" while a makeup was still due. New api._payments_for_plan() also keeps those two unlinked kinds (makeup only when its date matches one of the plan's own payments).
  • Fixed: balance / progress / plan end inflated by deliberately cancelled plans. get_mandate_gc_summary and the daily GHL sync both counted every cancelled payment as owed, so a client who changed order (old plans cancelled, new plan on the same mandate) showed e.g. Balance £4,856.66, 5/49 and a 2028 plan end in GHL. New shared api.summarize_mandate_payments(): cancelled payments only count when the mandate itself is dead; a failed payment replaced by a live "Makeup payment" is one instalment, and the in-flight makeup counts as owed until collected. Daily sync now uses it (mandate status taken from the mandate list).
  • Fixed: "all our tags vanished" (4th recurrence) — the test suite was overwriting the live SideKick_GC.ini. GCConfig() with no INI path falls back to a relative SideKick_GC.ini, and load_config() finds the project INI via SCRIPT_DIR, so tests that saved settings rewrote GHL field mappings, tags and templates with blanks (and, via save_all(), the GHL API key in the keyring/credentials.json). New tests/conftest.py sandboxes cwd, %APPDATA%, config.SCRIPT_DIR and the keyring for every run. Documented in .github/instructions/SideKick_GC.instructions.md §12a.
  • Notifications tables unified: the events table and Bank Payers table now share one column layout (Date, Customer, Email, Shoot, Status, Details, Payments, Amount, Total, GHL Tag, Actioned, Actions) — columns with no data for a table stay blank. The last Actions column holds four icon buttons on both tables: ProSelect, GHL, Open Client and Send Statement (+ ✕ on bank payers). Send Statement on an events row reads the shoot's PSA balance, asks for confirmation, then sends the owing statement; disabled on completed plans and when the shoot/GHL contact/message field is unknown.
  • Notifications table: Payments (6/9), Amount, Total, Shoot and an Open column (ProSelect / GHL buttons) plus an "Updating current data…" progress bar; Settings: About moved into the side menu (opens on it), "Open on launch" tab dropdown (DefaultTab), vertical Application buttons.
  • Bridge rate-limit burst guard: GoCardless, GHL and Light Blue bridges now enforce a thread-safe minimum interval between consecutive calls (shared 300ms for GC/GHL via BRIDGE_MIN_INTERVAL_S, dedicated 1.5s for Light Blue via LB_MIN_INTERVAL_S), replacing the per-worker 1.5s drips; GHL 429 Retry-After retry behaviour is unchanged; the Daily Sync worker's hand-rolled GoCardless calls now go through the bridge (CONTRACT.md compliance); new gocardless_core/throttle.py; policy documented in gocardless_core/CONTRACT.md.
  • Bank-transfer statement reference: owing statements now quote the numeric part of the shoot reference (P26027P → 26027) on the "Reference" line clients use when paying by bank transfer — new shoot_ref_digits() helper (bank_payers.py) applied to both the Client-tab and Notifications-tab owing-statement builders. The Client tab also adopts the shoot from the bank-payer record (_show_bank_payer_statement), so a payer's statement quotes the shoot instead of the surname fallback and the PSA balance refresh runs. Previously the full shoot ref (or the surname) was shown.
  • Starling bank-feed provider: Settings → Bank Feed now has a provider dropdown — Nordigen (unchanged Metro feed) or Starling. Starling mode reads balances + transactions directly from the Starling API (personal access token, read-only scopes) and caches them in %APPDATA%\SideKick_GC, so the Banking tab works on an exe-only machine with no SideKick_Xero ledger. Amounts are normalised from unsigned minorUnits + direction, SETTLED-only, UPSERTed by feedItemUid, with a 5-minute changesSince overlap and 429 Retry-After back-off.
  • Worker shutdown join (fix): app exit now requests interruption and joins running worker QThreads — shutdown_workers() in workers.py, called from MainWindow.closeEvent — and PsaBalanceWorker polls its subprocess so it can stop early on shutdown. Closes a production exit path that could abort (0xC0000409) by destroying a live worker thread.
  • Amend / Defer date preservation (fix): deferring a schedule whose paylines have weekend-adjusted days (21st with occasional 22/23) no longer splits the plan into a deposit + shifted schedule. The first payment now splits only on a differing amount, and every payline's explicit date is preserved verbatim through schedule creation. Live bug: P26102P defer jumped Oct → Dec and flattened all dates to the 23rd.
  • Amend / Defer payment-plan flow (CLI verbs for SideKick_PS): new --reconcile-plans <mandate> (per-plan paid/total/dates for the PSA double-check), per-plan by-ID --cancel-plans-for <plan_id> [--apply-cancel-tag], and --apply-hold <plan_id> — cancelling only the plan the reconcile step matched (never mandate-wide), then applying configurable gc-on-hold / gc-plan-cancelled tags and updating the Payment Status field. GoCardless cannot amend a schedule's dates (update = metadata only), so deferrals are cancel + recreate with --bump-months.
  • PROPER-cased addresses on Light Blue sync: the sync payload now title-cases every address word (18 the cedars → 18 The Cedars, harpenden → Harpenden) via the new proper_address helper, reusing the Mc/O'/hyphen rules. Street, city, and county previously passed through ascii_clean untouched.
  • Single Stage-2 provider (SimplyPostcode): getAddress.io was dead weight — its original operator ceased UK operations in Feb 2026 (High Court ruling) and the reincarnated service 401s on every endpoint except /get. The Postcode page now shows one provider: the dropdown is gone, SimplyPostcode (Royal Mail PAF) is the single key field, and PostcodeAddressProvider defaults to simplypostcode. The setting and the getAddress plumbing behind it are kept deliberately — dormant, but the seam for a provider picker and loadable per-provider setting packs without a future config migration.
  • [saved]-prefix tag combos: Light Blue's trigger-tag combo and both Notifications combos (cancel-tag, completed-tag) now show [saved] <tag> when the saved value hasn't been confirmed against a live GHL fetch (deleted/renamed/not-yet-fetched) — matching the GHL Field Mapping page convention. currentData() holds the clean value so the prefix is never persisted on save.
  • Narrower cards: Payments tab capped to 400px; Payment Plans left column (Plan Details + Downpayment) capped to 500px.

> Native replacement for the dead Zapier/Sheets postcode pipeline. When a

> GHL contact is tagged, SideKick_GC looks up the postcode or full address

> and writes the corrected details back onto the contact (the write-back

> direction — Light Blue sync reads GHL, this writes GHL).

  • --silent CLI flag: Create payment plans headlessly without launching the GUI — requires --mandate-id, --paylines, and --plan-name; parses paylines, applies statement label prefix, creates the instalment schedule, writes result file, and exits
  • --cancel-plans CLI command: Cancel all active plans on a mandate — handles subscriptions, instalment schedules, and pending one-off payments (deposits)
  • cancel_mandate_plans() API function: Iterates all plans on a mandate and cancels active subscriptions, instalment schedules, and pending/submitted one-off payments
  • cancel_payment() API function: Cancel an individual pending payment by ID
  • cancel_instalment_schedule() API function: Cancel an instalment schedule by ID

Improvements

  • has_cli_command() recognises --silent: Silent mode with --mandate-id is now treated as a CLI command, bypassing GUI launch

v1.1.1 (2026-03-05)

New Features

  • Close to Tray option: New "Close to system tray" checkbox in Settings — when enabled, clicking X hides the window to the system tray; when disabled (default), X minimises to the taskbar
  • Toast on Mandate Cancellation: New "Show Windows notification on mandate cancellation" checkbox in Settings — displays a Windows toast via the system tray when polling detects bank-cancelled mandates (enabled by default)
  • Exit Program button: Red "⏻ Exit" button in Settings to fully quit the application with a confirmation warning if notification polling is active
  • Polling-active exit warning: Exiting via Settings or tray menu now warns if notification polling is running, reminding that SideKick needs to stay running in the background for polling to work

Improvements

  • X button behaviour: Clicking the window X button now minimises to taskbar (or hides to tray if enabled) instead of closing — the app always stays running
  • Desktop Shortcut button: Renamed to "Desktop Shortcut" with the SideKick_GC app icon instead of emoji
  • Smaller checkboxes & radio buttons: Reduced indicator size to 14px and font to 9pt with 6px spacing for a cleaner, more compact look
  • Settings layout: Bottom-justified Desktop Shortcut and Exit buttons on the same row with matching height

v1.1.0 (2026-03-04)

New Features

  • Payments Tab: New "💷 Payments" tab with two modes — single payments and subscriptions — mirroring GoCardless dashboard functionality
  • Single Payments: Create one-off payments against an active mandate with amount, charge date, description, reference, and metadata
  • Subscriptions: Create recurring open-ended subscriptions with configurable frequency (weekly/monthly/yearly), interval, day-of-month, and end condition (indefinite / fixed count / end date)
  • Subscription API: New create_subscription() and cancel_subscription() API functions calling GoCardless /subscriptions endpoint
  • Inline Prefix Label: Plan name and subscription name inputs show the Statement Label prefix inline as a non-editable label, so the user sees the full bank statement name without being able to edit the prefix (configured in Settings)

Improvements

  • Tab Layout: Payments tab inserted at index 2 between Payment Plans and Stale Mandates; all tab indices and --gui shortcuts updated
  • Mandate Forwarding: Client tab mandate ID now forwarded to both Payment Plans and Payments tabs automatically
  • Config Propagation: Settings changes propagated to the new Payments tab alongside all existing tabs

Models

  • SubscriptionResult — result of creating a recurring subscription
  • CancelSubscriptionResult — result of cancelling a subscription

Workers

  • CreateSinglePaymentWorker — background thread for one-off payment creation
  • CreateSubscriptionWorker — background thread for subscription creation
  • CancelSubscriptionWorker — background thread for subscription cancellation

v1.0.0 (2026-03-01)

Initial Release

  • CLI: Full GoCardless CLI with 100% parity to legacy gocardless_api.py commands
  • GUI: PySide6 dark-themed tabbed interface with Client, Payment Plans, Stale Mandates, Notifications, Settings, and About tabs
  • Client Tab: GHL contact search, Chrome import, manual entry, mandate lookup with QR code billing request flow
  • Payment Plans Tab: Instalment schedule creation with deposit, rounding control, recurring intervals, and live schedule preview table
  • Stale Mandates Tab: Find and batch-cancel stale or empty mandates with progress reporting
  • Notifications Tab: Background polling for bank-cancelled mandates with GHL tag auto-apply
  • Settings Tab: GoCardless token management, GHL integration, email/SMS template selection, statement label, currency
  • System Tray: Minimize to tray with context menu (Show, Settings, Restart, Exit)
  • CLI Injection: Full --client-email, --client-name, --balance, --gui TAB argument support for external caller integration
  • Result File: --result-file writes payline JSON for ProSelect payment method injection
